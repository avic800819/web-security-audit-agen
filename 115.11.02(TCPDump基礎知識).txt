【TCPDump 完整實戰重點筆記】
==================================================

一、 核心觀念與架構
--------------------------------------------------
1. 定義：Unix/Linux 環境下強大的命令列封包分析工具，可在無 GUI（終端機、SSH）環境直接擷取與解析網路資料幀[cite: 1]。
2. 底層機制：依賴 pcap / libpcap 函式庫，並藉由網卡的「混雜模式（Promiscuous Mode）」接收同網段廣播的所有封包，不限於發往本機的流量[cite: 1]。
3. 權限需求：直接存取原始網路封包屬於底層硬體操作，必須使用 root / administrator 權限（通常搭配 sudo 執行）[cite: 1]。
4. 預設儲存格式：PCAP 格式檔案（可完整匯入 Wireshark 進行深度排錯或離線取證）[cite: 2, 12]。


二、 常用環境指令
--------------------------------------------------
* 檢查系統中是否存在 tcpdump：
  which tcpdump[cite: 1]
  （常見安裝路徑：/usr/sbin/tcpdump）[cite: 1]

* 安裝指令（Debian / Ubuntu / Kali）：
  sudo apt install tcpdump[cite: 1]

* 查詢安裝版本與相依函式庫：
  sudo tcpdump --version[cite: 2]

* 查閱官方完整手冊：
  man tcpdump[cite: 4]


三、 核心常用參數對照表
--------------------------------------------------
-D              : 列出系統上所有可用於捕獲的網路介面（含虛擬、Loopback 等）[cite: 3, 4]
-i <介面名稱>   : 指定監聽的網路介面（如 -i eth0）[cite: 3, 4]
-n              : 禁用 IP 位址反查主機名稱（避免額外 DNS 查詢降低效能與干擾）[cite: 3, 5]
-nn             : 同時禁用 IP 反查與 Port 服務名稱解析（直接顯示數字 Port）
-e              : 顯示資料鏈結層（Ethernet）標頭資訊（可檢視來源/目的 MAC 位址）[cite: 3, 6]
-X              : 同時以十六進位（Hex）與 ASCII 格式輸出封包 Payload（方便看明文）[cite: 3, 7]
-XX             : 與 -X 相同，但額外印出乙太網路鏈結層標頭的 Hex/ASCII[cite: 3]
-v / -vv / -vvv : 增加詳細程度（依序顯示 TTL、IP ID、TCP Flags、Options 等完整欄位）[cite: 3, 8]
-s <長度>       : 指定每個封包抓取的最大長度（Snaplen，設為 0 代表抓取完整封包不截斷）[cite: 3]
-c <數量>       : 抓取指定封包數量後自動終止程式（如 -c 10）[cite: 3]
-S              : 顯示絕對 TCP 序號（Sequence Number），而非相對序號[cite: 3]
-q              : 快速安靜模式（Quiet），輸出較少通訊協定細節[cite: 3]
-w <檔案.pcap>  : 將抓取到的原始網路封包寫入檔案保存（避免終端機刷螢幕掉包）[cite: 3, 12]
-r <檔案.pcap>  : 從本機已儲存的 PCAP 檔案中讀取並解析流量[cite: 3, 12]


四、 實戰常用指令組合
--------------------------------------------------
1. 列出目前主機可監聽的介面編號與名稱：
   sudo tcpdump -D[cite: 4]

2. 監聽 eth0，不解析主機名稱（最基本抓包）：
   sudo tcpdump -i eth0 -n[cite: 5]

3. 監聽 eth0，同時查看 MAC 位址與十六進位明文內容：
   sudo tcpdump -i eth0 -nn -e -X

4. 實戰排錯與鑑識推薦組合（純數字 + 詳細輸出 + 完整 Payload 檢視）：
   sudo tcpdump -i eth0 -nnvvXX[cite: 8, 9]

5. 封包擷取並寫入檔案（藍隊取證／避免終端機掉包）：
   sudo tcpdump -i eth0 -w ~/output.pcap[cite: 12]

6. 離線讀取 PCAP 檔案並以 ASCII 形式分析封包內容：
   sudo tcpdump -r ~/output.pcap -X[cite: 12, 13]


五、 TCP 轉儲輸出欄位解讀（TCPDump Shell 分解）
--------------------------------------------------
範例單行輸出：
17:39:26.505372 IP 172.16.146.2.21 > 172.16.146.1.49769: Flags [P.], seq 1:77, ack 17, win 509, options [...], length 76: FTP: 220 Welcome to the PowerBroker FTP Service.[cite: 10, 11]

欄位解析：
1. 時間戳記 (Timestamp)  : 17:39:26.505372（格式為 時:分:秒.微秒）[cite: 10, 11]
2. 協定 (Protocol)        : IP（網路層協定，代表此介面上傳輸的是 IP 封包）[cite: 10, 11]
3. 來源 IP 與埠號        : 172.16.146.2.21（格式為 IP.port，此處來源埠為 21/FTP）[cite: 10, 11]
4. 流量方向符號          : >（代表流量從來源端發送到目的端）[cite: 10, 11]
5. 目的 IP 與埠號        : 172.16.146.1.49769（此處為客戶端臨時 Port 49769）[cite: 10, 11]
6. TCP 旗標 (Flags)       : Flags [P.]（代表此封包啟用之控制旗標）[cite: 10, 11]
   * 常見旗標代號：
     - [S] : SYN（連線請求）
     - [.] : ACK（確認收包）
     - [P] : PSH（Push，要求接收方儘快將資料交給應用層）
     - [F] : FIN（結束連線）
     - [R] : RST（強制重置連線）
7. 序號 (Sequence)        : seq 1:77（包含的資料位元組區間，此處代表發送了 76 bytes）[cite: 10, 11]
8. 確認號 (Acknowledgment): ack 17（告知對方已收到序號 16，期望收到下一個為 17）[cite: 10, 11]
9. 接收視窗大小 (Window)  : win 509（接收緩衝區大小）[cite: 10, 11]
10. 額外選項 (Options)    : options [nop,nop,TS val...]（TCP 延伸參數，如選擇性確認、時間戳）[cite: 10, 11]
11. 負載長度 (Length)     : length 76（應用層資料長度為 76 位元組）[cite: 10, 11]
12. 應用層協議解析/明文   : FTP: 220 Welcome to the...（TCPDump 自動解碼之明文內容）[cite: 10, 11]


六、 檔案輸入／輸出（I/O）實務技巧
--------------------------------------------------
1. 為什麼要存檔（-w）？
   - 網路流量龐大時，終端機輸出速度跟不上會導致掉包[cite: 12]。
   - 封包資料若無限制寫入磁碟，容量很快會耗盡，實務上通常搭配精確的過濾器或寫 Bash 腳本進行特定格式分析[cite: 11, 12]。
2. 存檔指令範例：
   sudo tcpdump -i eth0 -w ~/output.pcap[cite: 12]
   （執行後終端機不會刷出封包細節，只會累計 packets captured 計數）[cite: 12]
3. 離線分析範例：
   sudo tcpdump -r ~/output.pcap[cite: 12, 13]
   （從 PCAP 讀取時，依然可以自由搭配 -n, -X, -v 或過濾條件重新篩選）[cite: 13]

一、 核心概念與運作原理
--------------------------------------------------
1. 定位：Linux / Unix CLI 環境下最核心的網路封包嗅探與分析工具，適用於無 GUI（SSH、WebShell、終端機）環境[cite: 1]。
2. 權限需求：操作底層網路介面卡並開啟「混雜模式（Promiscuous Mode）」側錄全網段流量，必須具備 root / sudo 權限[cite: 1]。
3. 輸出與存檔：終端機即時刷新容易掉包，正式分析或大規模流量通常存為 PCAP 格式（-w 寫入、-r 讀取），方便日後離線分析或匯入 Wireshark[cite: 2, 3, 12]。


二、 核心參數速查表（功能與英文術語對照）
--------------------------------------------------
-D              : 列出系統上所有可監聽的網路介面（List Interfaces）[cite: 3, 4]
-i <介面>       : 指定要監聽的網路介面（如 -i eth0 或 -i tun0）[cite: 3, 4]
-n              : 停用主機名稱反查（Without hostname resolution，避免 DNS 延遲）[cite: 3, 5, 19]
-nn             : 同時停用主機名稱與 Port 服務名稱解析（純 IP 與純數字 Port）
-v / -vv / -vvv : 提高輸出詳細等級（Verbosity，顯示 TTL、IP ID、TCP Flags、Options）[cite: 3, 8, 19]
-X              : 以十六進位（HEX）與 ASCII 格式印出封包負載內容（看明文 Payload）[cite: 3, 7]
-XX             : 與 -X 相同，但額外印出乙太網路鏈結層（Ethernet Header）的內容[cite: 3]
-e              : 顯示資料鏈結層標頭（包含來源與目的之 MAC 位址）[cite: 3, 6]
-c <數量>       : 限制捕獲的封包「個數」（Count，達標後自動結束離開程式）[cite: 3, 21]
-s <長度>       : 限制每個封包擷取的「位元組長度」（Snaplen，-s 0 表示抓取完整封包不截斷）[cite: 3, 21]
-S              : 顯示 TCP「絕對序號」（Print absolute sequence numbers）[cite: 3]
-q              : 快速安靜模式（Quiet，僅輸出精簡通訊資訊）[cite: 3]
-w <檔案.pcap>  : 將原始封包完整寫入檔案（Write）[cite: 3, 12]
-r <檔案.pcap>  : 自本地 PCAP 檔案讀取流量進行離線分析（Read）[cite: 3, 12, 23]


三、 TCP 封包單行輸出結構解析
--------------------------------------------------
範例：
17:39:26.505372 IP 172.16.146.2.21 > 172.16.146.1.49769: Flags [P.], seq 1:77, ack 17, win 509, length 76: FTP: 220 Welcome to the PowerBroker FTP Service.[cite: 10, 11]

欄位拆解：
* 時間戳記   : 17:39:26.505372（時:分:秒.微秒）[cite: 10, 11]
* 協定       : IP（代表網路層封包）[cite: 10, 11]
* 來源端     : 172.16.146.2.21（IP 172.16.146.2，Port 21 為 FTP）[cite: 10, 11]
* 傳輸方向   : >（代表由來源流向目的端）[cite: 10, 11]
* 目的端     : 172.16.146.1.49769（IP 172.16.146.1，客戶端隨機 Port）[cite: 10, 11]
* TCP Flags  : Flags [P.]（P = PSH 推送資料，. = ACK 確認收包）[cite: 10, 11]
  - [S] : SYN（連線請求）
  - [.] : ACK（確認回覆）
  - [P] : PSH（要求立刻遞交應用層處理）
  - [F] : FIN（結束連線）
  - [R] : RST（強制重置/斷線）
* 序列號 (seq) : seq 1:77（相對序號，表示此封包包含 76 bytes 資料）[cite: 10, 11]
* 確認號 (ack) : ack 17（期望收到對方的下一個位元組序號）[cite: 10, 11]
* 視窗大小 (win): win 509（接收緩衝區長度）[cite: 10, 11]
* 應用層明文 : FTP: 220 Welcome to...（tcpdump 自動解碼之 Payload 明文）[cite: 10, 11]


四、 HTB Academy 解題作答避坑規範
--------------------------------------------------
1. 觀念二選一題型（Relative vs Absolute）：
   * 題目：捕捉過程使用的是絕對序號還是相對序號？
   * 避坑：不填中文、不填數字（如 1:135）。連線建立後從 1 開始計算即為相對序號。
   * 標準解答：relative

2. 參數合併題型（Combined Switches）：
   * 題目：不解析主機名 (-n)、詳細輸出 (-v)、ASCII/Hex (-X)、抓 100 個封包 (-c 100)
   * 避坑：翻譯常遺漏「verbose output (-v)」；依題目順序排列，無參數值的開關合在一起，帶數值的放最後。
   * 標準解答：-nvX -c 100

3. 增加詳細程度（Verbosity）：
   * 題目：哪個參數可以增加輸出的詳細程度？
   * 避坑：-X 是變更編碼格式，調高詳細等級的專業術語為 Verbose。
   * 標準解答：-v

4. 讀檔並解碼指令題（Full Command）：
   * 題目：讀取 /tmp/capture.pcap 並以 ASCII/HEX 顯示（遵循最佳實務）
   * 避坑：需輸入完整指令（包含 sudo 與 tcpdump），並將 -X 與 -r 合併為 -Xr。
   * 標準解答：sudo tcpdump -Xr /tmp/capture.pcap

5. 終端說明參考資料工具（Built-in Reference）：
   * 題目：哪些內建的終端幫助參考資料可以提供更多關於 TCPDump 的資訊？
   * 避坑：考的是工具名稱，勿輸入參數或指令全文（不要填 man tcpdump）。
   * 標準解答：man


五、 滲透測試與打靶機實戰情境應用
--------------------------------------------------
1. 檢驗盲眼指令注入（Blind RCE / Out-of-Band 測試）：
   * 情境：Web 介面有注入點但無畫面回顯，測試反彈 Shell 亦無連線，需確認指令是否真正被伺服器執行。
   * 指令：
     sudo tcpdump -i tun0 icmp
   * 攻擊酬載：在目標輸入 `ping -c 1 <你的HTB_IP>`。
   * 研判：若終端機出現 ICMP 封包，證實 RCE 成功觸發，僅 TCP 出站 Port 被防火牆封鎖。

2. 內網橫向與提權流量嗅探（Sniffing Credentials）：
   * 情境：在 Linux 靶機取得初階 Shell，內部有定時排程或系統管理員連線至明文傳輸服務（FTP/HTTP/Telnet）。
   * 指令：
     sudo tcpdump -i any -nn -X -s 0 port 21 or port 80
   * 成果：終端機右側 ASCII 區塊直接截獲明文傳輸的 USER 與 PASS 憑據。

3. 驗證攻擊腳本出站酬載（Payload Debugging）：
   * 情境：執行公開 Exploit 腳本攻擊目標無反應，需排查傳送的 HTTP Header 或 Payload 是否正確。
   * 指令：
     sudo tcpdump -i tun0 -nn -X host <目標IP> and tcp port 80
   * 成果：即時監看送往目標的請求內文，快速確認是路徑打錯、參數缺失還是 User-Agent 被阻擋。

4. 離線轉儲分析（Dump to PCAP）：
   * 情境：大量連線或複雜驗證交互時，終端機文字不利肉眼閱讀。
   * 指令：
     sudo tcpdump -i tun0 -w /tmp/capture.pcap -c 500
   * 流程：將檔案載回本地直接丟入 Wireshark，使用「Follow TCP Stream」以完整對話流形式進行深度逆向分析。

一、 核心運作觀念
--------------------------------------------------

二、 核心參數開關對照表（必考與實戰）
--------------------------------------------------
-D              : 列出本機所有可用於抓包的網路介面清單[cite: 3, 4]

-X              : 以 HEX（十六進位）與 ASCII 格式印出封包 Payload 內容[cite: 3, 7]
-XX             : 與 -X 相同，額外印出乙太網路鏈結層的 HEX/ASCII[cite: 3]
-A              : 以純 ASCII 文字格式印出內容（不顯示 HEX，最適合看 HTTP/FTP 明文）[cite: 44, 45]
-v / -vv / -vvv : 提高輸出詳細等級（Verbose，顯示 TTL、IP ID、TCP Flags、Options）[cite: 3, 8]
-c <數量>       : 限制抓取「封包個數」（Count，抓滿自動退出程式）[cite: 3, 21]

-S              : 顯示 TCP「絕對序號」（Print absolute sequence numbers）[cite: 3]
-q              : 安靜模式（Quiet），輸出較少協定細節[cite: 3]
-l              : 啟用「行緩衝模式」（Line-buffered），確保輸出能即時透過管道傳給 grep[cite: 25, 44, 46]

-r <檔案.pcap>  : 自本地 PCAP 檔案讀取流量進行離線分析[cite: 3, 12, 23]


三、 BPF（伯克利封包過濾器）語法精要
--------------------------------------------------
1. 主機與方向過濾：
   * host <IP>           : 雙向只要包含該主機即捕獲[cite: 27, 28]
   * src host <IP>       : 僅抓取「來源」為該主機的封包[cite: 28, 30]
   * dst host <IP>       : 僅抓取「目的」為該主機的封包[cite: 28, 30]
   * net <網段/掩碼>     : 監聽特定網段（如 net 172.16.146.0/24）[cite: 28, 32]
   * dst net <網段/掩碼> : 僅抓取送往該網段的流量[cite: 32, 33]

2. 埠號與協定過濾：
   * port <號碼>         : 指定單一埠號（如 port 80 或 port 21）[cite: 28, 35]
   * src port <號碼>     : 僅抓取來源埠為該號碼的封包[cite: 31, 32]
   * dst port <號碼>     : 僅抓取目的埠為該號碼的封包[cite: 35]
   * portrange <起-訖>   : 監聽連續範圍埠（如 portrange 0-1024）[cite: 28, 37]
   * tcp / udp / icmp    : 依協定名稱過濾[cite: 28, 34]
   * proto <號碼>        : 依協定編號過濾（proto 1=ICMP、proto 6=TCP、proto 17=UDP）[cite: 34, 35]

3. 封包大小與邏輯運算：
   * less <大小>         : 僅抓取小於該長度的封包（如 less 64 抓心跳/探測包）[cite: 28, 38]
   * greater <大小>      : 僅抓取大於該長度的封包（如 greater 500 抓檔案/網頁資料）[cite: 28, 37, 39]
   * and（&&）           : 條件且（如 src host 10.10.1.1 and port 80）[cite: 28, 30, 35]
   * or（||）            : 條件或（如 port 80 or port 443）[cite: 28, 35]
   * not（!）            : 排除條件（如 not icmp、not port 22）[cite: 25, 28]

4. 底層 TCP 旗標位元運算：
   * tcpdump 'tcp[13] & 2 != 0' : 抓取所有包含 SYN 旗標的連線請求封包[cite: 46, 47]


四、 TCP 單行輸出欄位解析
--------------------------------------------------
範例：
17:39:26.505372 IP 172.16.146.2.21 > 172.16.146.1.49769: Flags [P.], seq 1:77, ack 17, win 509, length 76: FTP: 220 Welcome...[cite: 10]

* 時間戳記   : 17:39:26.505372（時:分:秒.微秒）[cite: 10]
* 協定       : IP（網路層協定）[cite: 10]
* 來源端     : 172.16.146.2.21（來源 IP 與 Port，21 為 FTP）[cite: 10]
* 方向指示   : >（由來源傳送到目的端）[cite: 10]
* 目的端     : 172.16.146.1.49769（目的 IP 與臨時 Port）[cite: 10]
* Flags 標記 : Flags [P.]（P = PSH 推送資料，. = ACK 確認收包）[cite: 10]
  - [S] : SYN（連線請求）[cite: 11, 16]
  - [.] : ACK（確認回覆）[cite: 10, 11]
  - [P] : PSH（要求立刻遞交應用層處理）[cite: 10, 11]
  - [F] : FIN（結束連線）[cite: 11]
  - [R] : RST（強制中斷連線）
* seq 1:77   : 相對序號，表示此封包包含 76 bytes 資料長度[cite: 10, 11]
* ack 17     : 確認號，告知對方已收到序號 16，期望下一個收到 17[cite: 10, 11]
* win 509    : 接收視窗大小（緩衝區空間）[cite: 10, 11]
* 應用層明文 : FTP: 220 Welcome...（Payload 內容自動解碼）[cite: 10]

【Wireshark 與 TShark 分析核心重點筆記】
==================================================

一、 介面架構：三大核心窗格（Three Panes）
--------------------------------------------------
1. Packet List（封包清單窗格）[cite: 38, 47]：
   - 位於最上方，以表格逐行列出每個封包的摘要資訊（編號、時間、來源/目的 IP、協定、長度、Info）[cite: 37, 47]。
2. Packet Details（封包詳細資訊窗格）[cite: 38, 47]：
   - 位於中間，依 OSI 模型由下至上將各層協定（Frame、Ethernet、IP、TCP/UDP、Application）展開為樹狀結構檢視。
3. Packet Bytes（封包位元組窗格）[cite: 38, 47]：
   - 位於最下方，左側顯示原始 16 進位（Hex），右側顯示對應的 ASCII 明文內容[cite: 37, 47]。


二、 兩大過濾器本質區別（核心必考點）
--------------------------------------------------
| 比較項目 | Capture Filters（擷取過濾器）[cite: 44] | Display Filters（顯示過濾器）[cite: 44, 47] |
| :--- | :--- | :--- |
| 設定時間點 | 開始抓包「之前」設定[cite: 44] | 抓包中或抓完後隨時套用[cite: 44, 47] |
| 語法標準 | BPF 語法（同 tcpdump）[cite: 44] | Wireshark 專屬語法（物件導向式）[cite: 47] |
| 封包處理方式 | 未符合條件的封包直接丟棄，不佔硬碟[cite: 44] | 僅隱藏顯示，所有封包仍完整保留於檔案中[cite: 48] |
| 輸入位置 | Capture Options 視窗內的綠色輸入框[cite: 46] | 視窗頂部的「Apply a display filter」搜尋列[cite: 48] |


三、 常用過濾語法對照表
--------------------------------------------------
1. 指定主機 IP：
   - Capture Filter : host 10.10.10.5[cite: 44]
   - Display Filter : ip.addr == 10.10.10.5[cite: 47]

2. 指定來源 / 目的：
   - Capture Filter : src host 10.10.10.5 / dst host 10.10.10.5[cite: 30, 44]
   - Display Filter : ip.src == 10.10.10.5 / ip.dst == 10.10.10.5[cite: 47]

3. 指定網段（CIDR）：
   - Capture Filter : net 192.168.1.0/24[cite: 32, 44]
   - Display Filter : ip.addr == 192.168.1.0/24[cite: 47]

4. 指定連接埠：
   - Capture Filter : port 80 或 portrange 1-1024[cite: 35, 37, 44]
   - Display Filter : tcp.port == 80 或 udp.port == 53[cite: 47]

5. 排除特定條件：
   - Capture Filter : not icmp 或 ! port 22[cite: 25, 43, 44]
   - Display Filter : !icmp 或 !(tcp.port == 22)[cite: 47]


四、 命令列工具補充
--------------------------------------------------
1. TShark（CLI 版 Wireshark）[cite: 35]：
   - tshark -D             : 列出可用的網路介面[cite: 37, 41, 42]
   - tshark -i eth0        : 指定在 eth0 介面抓包[cite: 41, 42]
   - tshark -i eth0 -f "..." : 套用 Capture Filter（BPF 語法）[cite: 41, 43]
   - tshark -r test.pcap   : 讀取離線 pcap 檔案[cite: 41, 42]
   - tshark -x             : 印出 Hex 與 ASCII 內容[cite: 41]

2. Termshark（文字終端機介面）[cite: 44]：
   - 在沒有 X-Window GUI 的純 SSH 終端機下，提供如同 Wireshark 三大窗格的互動式操作介面[cite: 44, 45, 46]。

【Wireshark 進階重組、還原與統計分析核心筆記】
==================================================

一、 串流重組追蹤（Follow Stream）
--------------------------------------------------
1. 核心功能：
   將經過 TCP 分段（Segmentation）傳輸的多個封包重新拼裝，還原應用層雙向完整對話內容。

2. 操作方式：
   對目標封包按右鍵 -> Follow -> TCP Stream（或 HTTP Stream / UDP Stream）。

3. 呈現介面顏色識別：
   * 紅色文字：客戶端發送至伺服器的請求內容（Client -> Server）
   * 藍色文字：伺服器回傳給客戶端的回應內容（Server -> Client）[cite: 49]

4. 對應顯示過濾器：
   * tcp.stream eq <編號>（例如：tcp.stream eq 0 僅檢視第一個連線會話的所有相關封包）[cite: 49]


二、 檔案提取還原（Export Objects）
--------------------------------------------------
1. 核心功能：
   從已捕獲的未加密網路流量中，自動重構並匯出傳輸的實體檔案（如 Web 傳輸的圖片、壓縮包、惡意腳本）[cite: 49, 50]。

2. 操作方式：
   頂部功能表 -> File（檔案）-> Export Objects（匯出物件）-> 選擇對應協定（HTTP / SMB / TFTP / IMF）。

3. 限制條件：
   傳輸過程必須為明文協定（如 HTTP 或未加密 SMB）[cite: 50]，若為 TLS/HTTPS 則須先載入金鑰解密[cite: 39]。


三、 統計分析功能（Statistics Menu）
--------------------------------------------------
1. Protocol Hierarchy（協定階層統計）：
   - 樹狀圖顯示各層協定所佔百分比與封包數量，用於迅速研判整體流量類型（如大量 DNS、大量未知 TCP）[cite: 47]。

2. Conversations（會話通訊統計）[cite: 47]：
   - 列出所有主機對之間的 IP、Port 通訊對象與總傳輸位元組，快速找出流量最大的通訊節點[cite: 47]。

3. Endpoints（端點統計）：
   - 列出參與通訊的所有獨立主機 IP 與 MAC 清單。

4. Expert Information（專家資訊）[cite: 48]：
   - Wireshark 自動標記的異常訊息（如重傳 TCP Retransmission、連線中斷 RST、畸形封包 Malformed Packet）。

【Wireshark 封包剖析實戰：檔案還原與遠端協定分析】
==================================================

一、 HTTP 檔案傳輸取證標準流程
--------------------------------------------------
1. 快速過濾 Web 流量：
   * Display Filter 輸入：http[cite: 47, 52]
   * 排除掉握手 ACK 雜訊，僅檢視 HTTP GET/POST 與 200 OK 回應。

2. 辨識圖片與檔案格式（Magic Bytes / 標記）：
   * JPEG 圖片特徵：Payload 開頭包含 JFIF 標記[cite: 53]。
   * PNG 圖片特徵 ：開頭為 .PNG。
   * PDF 文件特徵 ：開頭為 %PDF。

3. 檔案還原兩大技巧：
   * 技巧 A（全自動）：File -> Export Objects -> HTTP -> 點選檔案並 Save[cite: 50]。
   * 技巧 B（串流法）：封包右鍵 -> Follow -> TCP Stream -> 下方「顯示與儲存資料為」選「原始資料 (Raw)」-> 另存為 .jpg 或 .bin[cite: 48, 49]。


二、 遠端實驗室桌面連線（FreeRDP 指令）
--------------------------------------------------
* 指令語法：
  xfreerdp /v:<Target_IP> /u:htb-student /p:'HTB_Academy_stdnt!'[cite: 54]

* 常用優化參數：
  /cert:ignore    : 忽略自簽憑證警告
  /dynamic-resolution : 隨視窗大小自動調整解析度
  +clipboard      : 啟用本機與遠端桌面剪貼簿共享


三、 FTP 雙通道協定分析要點
--------------------------------------------------
1. 控制通道（Port 21）[cite: 10, 54]：
   * 顯示過濾器：ftp[cite: 54, 55]
   * 監聽內容：USER、PASS 明文帳密、CWD 目錄切換、PORT/PASV 模式協商[cite: 54, 55]。

2. 資料通道（ftp-data / 動態高位埠）[cite: 55]：
   * 顯示過濾器：ftp-data[cite: 55]
   * 監聽內容：真正透過 LIST 列出的檔案清單、下載或上傳的實體檔案內容（同樣可用 Follow TCP Stream 還原）。

【Wireshark 加密流量解密核心筆記（RDP / TLS）】
==================================================

一、 核心概念
--------------------------------------------------
1. 傳輸加密盲點：
   * RDP（預設 Port 3389）底層常以 TLS 加密傳輸，直接過濾「rdp」會完全無資料（顯示為 TLS 加密流量）[cite: 34]。
2. 解密先決條件：
   * 必須取得伺服器端的 RSA 私鑰（.key 檔案）[cite: 33, 36]，或現代 TLS 1.3 的 Pre-Master Secret（SSLKEYLOGFILE）[cite: 35]。

二、 Wireshark 匯入金鑰步驟
--------------------------------------------------
1. 進入設定：
   Edit（編輯）-> Preferences（偏好設定）-> Protocols（協定）-> 選擇「TLS」[cite: 35]。
2. 配置金鑰列表：
   點擊「RSA keys list」旁邊的「Edit...」按鈕[cite: 35]。
3. 新增規則項目[cite: 36]：
   * IP Address : 目標伺服器 IP（如 10.129.43.29）[cite: 36]
   * Port       : 3389（或指定之連接埠）[cite: 36]
   * Protocol   : tpkt（或 rdp）[cite: 36]
   * Key File   : 瀏覽選取伺服器私鑰路徑（server.key）[cite: 36]
4. 成果驗證：
   儲存後返回主畫面，上方 Display Filter 輸入「rdp」，原本的 TLS 密文會被自動解譯為 RDP PDU 結構（包含連線交握、使用者名稱等）[cite: 37]。
